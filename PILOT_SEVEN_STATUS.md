## 3. What is `derived: true` on Mudon (P1 geometry)

We persist **room polygons only** (normalised), so the whole wall/opening/scale
layer is derived. Every value below is flagged `derived: true` and surfaced in
the UI `derivedNotes`. **The QS/engineer should treat these as placeholders.**

- **All 59 walls** — derived from shared/boundary polygon edges (none persisted).
- **Wall thickness** — default **200 mm** for every wall.
- **`is_structural`** — **always `null`** (the parse cannot tell structural from
  partition). This is why P6 fires a structural-uncertainty rule on any wall
  change (see §5).
- **Openings** — **empty**. No doors/windows are invented; door-swing, opening
  widths, and lintels are all absent from the drawings.
- **Ceiling height** — default **2.9 m** every room (drives wall/plaster/paint
  and 3D extrusion).
- **Metric scale** — metres are derived from `total_area_m2` via a single
  isotropic unit→metre factor; there is **no surveyed scale bar**. Consequence:
  the dimensioned area of an individual room can diverge from its DB `area_m2`
  (worst on Mudon: **Passage, 10.5 vs 5.2 m² — 103%**). The plan-sheet dimension
  chains reconcile to the gross envelope, not per-room net areas.
- **North** default 0°, **level** default "first_floor".

Net room areas sum to **145.7 m²**; gross envelope is **178.5 m²** (Δ 32.8 m² =
wall footprint + circulation). Both figures are correct for their purpose — they
are not meant to be equal.

**Ask for the QS/engineer:** a site visit to confirm wall structural status,
real wall thicknesses, opening schedule, and true room dimensions would replace
the largest block of derived values.

## 6. Render cost delta from staging (P7)

**Effectively zero.** Staging appends a ~60-token STAGING block to the **same
single** `google/nano-banana` edit call — it does not add an image generation or
a model invocation. The photo path stays one edit call; the off-plan path stays
one base + one edit call. Replicate bills per prediction/compute, not per prompt
token, so incremental cost per staged image is negligible. Staging only extends
the prompt (the cache key), so caching and the tweak/iterate flow are unchanged:
flag off vs on are simply two distinct prompts → two distinct cache entries.

_The one still-billable check:_ the flag-off-vs-on **image pair** (visibly
furnished vs bare, architecture unchanged) needs a live Replicate render and was
not run to avoid spend — screenshot `09` covers it when captured.
